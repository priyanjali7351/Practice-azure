Backend Blueprint — What to Build
  • 1
    Create a Function App in Azure Portal → Compute → Function App. Choose Python 3.11, Consumption plan, and a region near you.
  • 2
    Add an HTTP Trigger function. In VS Code with the Azure Functions extension, run: func new → HTTP trigger → name it hello.
  • 3
    Write the function code in function_app.py:
import azure.functions as func import json app = func.FunctionApp(http_auth_level=func.AuthLevel.ANONYMOUS) # Route: POST /api/hello @app.route(route="hello", methods=["POST"]) def hello(req: func.HttpRequest) -> func.HttpResponse: body = req.get_json() name = body.get("name", "World") return func.HttpResponse( json.dumps({"message": f"Hello, {name}! from Azure ⚡"}), mimetype="application/json" )
  • 4
    Enable CORS in the Function App settings → CORS → add * (or your local origin) so the browser can call it.
  • 5
    Deploy with func azure functionapp publish <app-name> or via VS Code's "Deploy to Function App" button.
💡 The URL pattern is: https://<app>.azurewebsites.net/api/hello. Paste this in the top bar's base URL field.

Backend Blueprint — CRUD API
  • 1
    Three routes in one Function App:
    GET /api/tasks → return all tasks
    POST /api/tasks → add a task
    DELETE /api/tasks/{id} → remove a task
  • 2
    Start with an in-memory dict (global variable in Python). It resets on cold start — that's fine for learning.
tasks = {} # temporary in-memory store @app.route(route="tasks", methods=["GET","POST"]) def tasks_handler(req): if req.method == "GET": return func.HttpResponse(json.dumps(list(tasks.values())), mimetype="application/json") body = req.get_json() task_id = str(uuid.uuid4()) tasks[task_id] = {"id": task_id, **body} return func.HttpResponse(json.dumps(tasks[task_id]), status_code=201, mimetype="application/json")
  • 3
    Upgrade to Cosmos DB: Create a Cosmos DB account (Free tier!), add the connection string to local.settings.json and App Settings, then use the azure-cosmos SDK to replace the dict.
  • 4
    Test locally with func start. Each route will be at http://localhost:7071/api/tasks.

Backend Blueprint — Blob Trigger
  • 1
    Create a Storage Account in Azure Portal → Storage Accounts → create with LRS redundancy. Add a container called uploads.
  • 2
    HTTP Upload Function: Create a function that accepts a file (multipart or base64), then uses BlobServiceClient to upload to the container. This is what the Upload button calls.
from azure.storage.blob import BlobServiceClient @app.route(route="upload", methods=["POST"]) def upload_file(req): conn = os.environ["STORAGE_CONN"] client = BlobServiceClient.from_connection_string(conn) blob = client.get_blob_client( container="uploads", blob=filename) blob.upload_blob(req.get_body()) return func.HttpResponse("Uploaded!")
  • 3
    Blob Trigger Function: Fires automatically when a file lands in the container. Great for image resizing, virus scanning, CSV processing, etc.
@app.blob_trigger( arg_name="blob", path="uploads/{name}", connection="STORAGE_CONN") def process_upload(blob: func.InputStream): logging.info(f"Processing: {blob.name}, size={blob.length}") # Add your processing logic here
⚠️ Add the Storage connection string to both local.settings.json (local dev) and Azure Function App Settings (production).

Backend Blueprint — Timer Functions
  • 1
    Cron expression format for Azure: {second} {minute} {hour} {day} {month} {weekday}
    Azure uses 6-part cron (unlike Unix 5-part). The extra leading field is seconds.
  • 2
    Define a timer trigger function:
@app.timer_trigger( schedule="0 0 8 * * *", # daily at 8am UTC arg_name="timer", run_on_startup=False) def daily_report(timer: func.TimerRequest): if timer.past_due: logging.warning("Timer is past due!") logging.info("Generating daily report...") # your job logic here
  • 3
    Add a companion HTTP function that returns the last-run timestamp so your UI can display it. Store the timestamp in Table Storage or a global variable.
  • 4
    Test locally: Set run_on_startup: true in local.settings.json to trigger immediately when you run func start.
💡 Common cron patterns:
Every minute: 0 */1 * * * *
Every hour: 0 0 */1 * * *
Weekdays 9am: 0 0 9 * * 1-5

5. Azure Key Vault — Secrets Management

Never hardcode credentials. Store DB passwords, API keys, and connection strings in Key Vault. Your Function fetches them at runtime using Managed Identity.

Backend Blueprint — Key Vault Integration
  • 1
    Create a Key Vault: Azure Portal → Key Vault → Create. Choose the same region as your Function App.
  • 2
    Enable Managed Identity on your Function App: Function App → Identity → System Assigned → toggle ON. Copy the Object ID.
  • 3
    Grant access: Key Vault → Access Policies → Add Policy → select Get secret permission → paste the Function App's Object ID.
  • 4
    Fetch secrets in Python using DefaultAzureCredential (automatically uses Managed Identity in Azure, your CLI login locally):
from azure.identity import DefaultAzureCredential from azure.keyvault.secrets import SecretClient VAULT_URL = os.environ["KEY_VAULT_URL"] credential = DefaultAzureCredential() client = SecretClient(VAULT_URL, credential) @app.route(route="secret", methods=["POST"]) def get_secret(req): name = req.get_json().get("name") secret = client.get_secret(name) masked = secret.value[:3] + "••••" return func.HttpResponse(json.dumps({"masked": masked}), mimetype="application/json")
✅ Best practice: reference Key Vault secrets directly in App Settings using @Microsoft.KeyVault(SecretUri=...) syntax — no code change needed!

Backend Blueprint — Observability
  • 1
    Create Application Insights: Azure Portal → Application Insights → Create. Link it to your Function App under Configuration → Application Insights.
  • 2
    Automatic telemetry: Once linked, Functions automatically send invocation logs, exceptions, and durations to App Insights — zero code change.
  • 3
    Custom metrics and events with the opencensus SDK:
from opencensus.ext.azure import log_exporter from opencensus.ext.azure.trace_exporter import AzureExporter # Or use the simple logging approach: logging.info("task_created", extra={ "custom_dimensions": { "task_id": task_id, "priority": priority } }) # Query in App Insights with KQL: # traces | where message == "task_created" # | summarize count() by tostring(customDimensions.priority)
  • 4
    Set up an Alert Rule: Monitor → Alerts → Create → choose metric "Failed requests" → threshold > 5 in 5 min → action group → email yourself.
  • 5
    Expose a /metrics HTTP Function that queries App Insights via the REST API and returns JSON for this dashboard.

local.settings.json Template
{ "IsEncrypted": false, "Values": { "AzureWebJobsStorage": "UseDevelopmentStorage=true", "FUNCTIONS_WORKER_RUNTIME": "python", "STORAGE_CONN": "<your-storage-conn-string>", "KEY_VAULT_URL": "https://<vault-name>.vault.azure.net/", "APPINSIGHTS_INSTRUMENTATIONKEY": "<your-key>" }, "Host": { "LocalHttpPort": 7071, "CORS": "*" } }
